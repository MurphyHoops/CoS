## 3.1.2: Reliable GitHub waits from the installed macOS app

CoS 3.1.2 fixes a durable-runtime integration bug that affected `session_wait(kind=github_run)` when the macOS app was launched normally from Finder or Applications.

The installed Electron app inherits the macOS GUI launch environment, which commonly omits Homebrew paths such as `/opt/homebrew/bin`. The GitHub wait provider previously spawned `gh` by bare command name, so a healthy GitHub CLI installation could still fail with `spawn gh ENOENT`. After repeated local monitor attempts, the wait would correctly fail closed and ask the executor to reconcile the external condition manually, but unattended work could not continue.

3.1.2 now resolves the GitHub CLI before monitoring a run. It checks the inherited PATH first and then standard platform locations, including Apple Silicon Homebrew (`/opt/homebrew/bin/gh`) and Intel Homebrew (`/usr/local/bin/gh`). The provider passes the resolved executable path directly to the shell-free command runner.

The durable semantics are unchanged: the exact repository/run id remains the wait identity, network-dependent waits still suspend with provider transport, and an unverifiable run never becomes a guessed success.

Regression coverage reproduces the macOS GUI PATH shape and asserts that Homebrew locations remain discoverable. App and companion remain on bridge protocol 15; the app/extension release version is 3.1.2.
