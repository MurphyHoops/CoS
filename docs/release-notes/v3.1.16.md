## 3.1.16: Terminal capacity and exact ChatGPT request compatibility

This is a local hotfix candidate based on the 3.1.15 development line; it is not a public release announcement.

### Terminal sessions

The 64-session limit now counts running OS children and pending asynchronous process starts, not exited processes whose output is still awaiting collection. Completed output remains addressable through the existing process ID and `write_stdin` path. Pending launch reservations are tracked separately to preserve the true live-child ceiling under concurrent requests.

### Page request identity

The extension's passive SSE/WebSocket observer and content script recognize both `wfr_` and UUID-form request IDs. Correlations require matching first-party request metadata and the exact current conversation, followed by the app's acknowledgement. Request ID syntax alone never authorizes a tool or adopts another conversation's process.

### Browser and packaging

The temporary-chat state detector gives priority to the visible checked sprite when sprites exist and uses native translated action labels only for sprite-less controls. The full package manifest and cross-platform packaging checks from the 3.1.15 branch are retained.

### Known limits

This release does not bypass ChatGPT history HTTP 429 responses or authorize a tool without exact conversation identity. Local test and launch verification do not imply that ChatGPT-side history or task delivery has recovered during provider rate limiting.
