## 3.1.5: Packaging integrity and Windows ARM release stability

CoS 3.1.5 is the corrected release after the 3.1.4 publish candidate failed before a GitHub Release was created.

### Packaging integrity

A locally built 3.1.4 app exposed a packaging hazard: when `node_modules` was symlinked from another checkout, electron-builder could package `@modelcontextprotocol/server` while omitting its runtime dependency `@modelcontextprotocol/core`. The resulting Electron main process failed at startup with:

```
Cannot find module '@modelcontextprotocol/core/internal'
```

3.1.5 makes the dependency explicit at the application level, refuses release packaging from a symlinked `node_modules` tree, and extends the native packaged-runtime smoke test to load the actual MCP server entry point. A package missing `@modelcontextprotocol/core/internal` now fails before it can be installed or published.

The supported release/local-package workflow is therefore a real checkout-local `npm ci` followed by packaging. Symlinked dependency trees remain fine for ordinary development/tests but are deliberately rejected for release packaging.

### Windows ARM publish failure

The 3.1.4 GitHub publish run reached all package jobs, but Windows ARM verification failed in the background-window capture test because a transient hosted-runner shell window closed after enumeration and before the next capture RPC. Production correctly rejected that stale HWND. The test now treats that exact window-disappearance condition the same way as the adjacent background-capture test: it exits the case because there is no longer a live background window whose focus behavior can be asserted. All other errors still fail.

App and companion are version 3.1.5. Bridge protocol remains 15.
