## 3.1.1: Durable Compact & Resume opening + exact companion diagnostics

CoS 3.1.1 is a focused reliability patch for two failures that can look similar from the user side: a continuation brief can be safely stored but fail to land in its replacement ChatGPT conversation, and Chrome can appear to have the right companion version while actually running a different unpacked directory.

### Compact & Resume: the handoff is the debt

A real 3.0 run exposed the failure boundary. The source chat successfully produced and stored its handoff brief, CoS started opening the replacement chat, but that browser carrier never reported back. Ten minutes later the manual continuation was abandoned. The local mission survived, but the requested continuation did not.

3.1.1 moves the lifetime boundary to the durable handoff:

- manual source-writing is still bounded: ten minutes normally, or one hour for a frozen Pro source selection whose hidden reasoning does not produce transcript progress;
- once the brief is durably captured, manual and automatic handoffs are app-owned opening debt rather than temporary browser work;
- a replacement carrier gets a 15-minute lease; if it is still provably pre-dispatch, that carrier may retire and a new carrier may claim the same exact brief;
- opening pickup continues at that cadence until exact commit or explicit cancellation instead of stopping after three attempts;
- restart restores the captured handoff rather than reinterpreting old wall-clock age as permission to discard it.

The safety boundary is unchanged and explicit: `dispatched-unresolved` and `sent` are not retryable merely because a tab, ACK or timer disappeared. CoS preserves the ambiguity fence and waits for exact evidence or an explicit user decision rather than typing the brief twice.

### Companion identity: version is not enough

Unpacked Chromium extensions are bound to a directory. Two directories can both say “3.1.1”, so a version comparison alone cannot prove that Chrome is running the extension tree shipped by the installed app.

Bridge protocol **15** adds an opaque companion-build identity:

- every companion request identifies its release build;
- `/hello` publishes the exact build identity the app expects;
- the desktop app distinguishes companion **detected**, **authorized**, authenticated HTTP **present**, wake-channel **connected**, and explicitly **disconnected** states;
- the desktop UI reports a stale unpacked-source mismatch even when the semantic version matches;
- the companion popup independently reports **Loaded copy mismatch** and shows both its own build identity and the app's expected build identity.

When that mismatch appears, use **Chat On Steroids → Setup → Open extension folder**, then open `chrome://extensions` and remove/reload the companion from that exact folder. Reload ChatGPT tabs after their active work has finished.

An explicit **Disconnect** remains durable and is not silently undone by the next poll. Reconnect from the companion popup under **Advanced → Connect**.

### Compatibility

The app and companion version together as **3.1.1**. Bridge protocol is **15**; a protocol-14 companion is intentionally incompatible because it cannot carry the exact companion-build identity required by this diagnostic contract.

Reload the unpacked companion from the extension folder shipped with the 3.1.1 app after updating.

### Regression coverage

The release adds focused coverage for:

- the reproduced 3.0 manual Compact & Resume failure after a brief was already captured;
- captured manual handoff retention across the former ten-minute opening timeout and app restart;
- safe pre-dispatch carrier release and exact-brief reclaim;
- fail-closed dispatched/sent continuation checkpoints;
- same-version stale unpacked-source detection;
- first-scan and cached-port companion-build discovery;
- app/package/manifest/protocol/companion-build release identity consistency.
