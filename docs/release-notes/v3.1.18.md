# CoS Classic 3.1.18 — Reliable pinned packaging downloads

Based on `main@7bc5a958d5808e8c4506282a363a6c61c3f00c8f`, adapting upstream [PR #1474](https://github.com/totec448-spec/chat-on-steroids/pull/1474) (2026-10-14, MIT) while preserving Classic's 3.x product and Durable Runtime.

## Packaging changes

- All three simple network downloaders (tunnel-client, ripgrep, native dependency prebuilds) use bounded `fetchWithRetry` for network resets, timeouts, HTTP 429 and HTTP 5xx, with per-attempt timeout and 2/5/10 second retry delays.
- HTTP 404/other permanent errors fail fast; checksums and lockfile integrity remain mandatory.
- The 730-source native license archive path already uses separate reviewed-source retry/mirror safeguards, left untouched.
- Paired app/companion build identity: `cos-3.1.18-packaging-retry-v1`; bridge protocol is still 15.

## Compatibility and deferred work

This release changes *build reliability*, not ChatGPT provider-pressure behavior or Goal/Loop semantics. Upstream PR #1475's `questionId`-anchored stalled-turn equivalence cannot be safely pasted into this fork without first migrating equivalent canonical question/response identity evidence. That remains a separate next milestone.
