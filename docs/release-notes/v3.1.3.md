## 3.1.3: Companion updates that survive app upgrades

CoS 3.1.3 fixes the recurring failure where the desktop app updated successfully but Chrome kept
running an older or unusable unpacked companion until the extension was removed and loaded again.

The packaged companion is now refreshed into its stable per-user folder before the browser bridge
starts. An update no longer replaces that Chrome-visible root directory: CoS stages and verifies
the new tree first, snapshots the old copy for recovery, then synchronizes children into the same
root. If the app stops during that refresh, the next start restores the last known-good contents
without changing the registered extension path.

The companion also learns the app's expected opaque build identity from `/hello`. When a running
worker is from the previous build, it records that expected build and asks Chrome to reload the
extension once from the stable folder. The persisted one-shot fence prevents a deliberately wrong
unpacked source from entering a reload loop. The existing service-worker startup recovery then
reinjects the companion into already-open ChatGPT tabs; if a tab still shows stale page state, a
normal browser-page refresh is enough. Manual chrome://extensions remove/re-load is now reserved
for the exceptional case where Chrome was loaded from a different directory altogether.

This release also updates the pinned OpenAI tunnel-client to v0.0.15 with verified SHA-256 values
for Windows, macOS and Linux on both x64 and arm64. The v3.1.2 publish job correctly failed because
its immutable tag still pinned v0.0.14; 3.1.3 carries the current pin instead of rewriting that
historical tag.

App and companion are version 3.1.3. Bridge protocol remains 15.
