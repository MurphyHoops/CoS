# CoS Classic 3.1.19 — Independently audited native-final safety fence

Canonical source base: `MurphyHoops/CoS main@5068eace7d1befba0c4268f958c1fd807883cc6e`, Classic 3.1.18.

## Root cause (reproduced before fix)

Classic `src/main/session/store.ts::readCompletedFinal` evaluated any later `turn_end` other than `completed` as new/unresolved work, including a `stalled` watchdog event for the **identical** turn received *after* a provider-identified final. An actual regression test reproduced the failed final check (`null` rather than the authoritative final). This could block a Goal/Loop turn from settling and postpone the next user-authorized continuation.

## Repair and limits

Allow only a later `turn_end(stalled)` whose turnId equals the canonical final's exact turnId and whose final includes a providerMessageId. No synthetic final or new queued message is created, and `stopped`, `failed`, `unknown`, unrelated turns and missing native identity are still blocking. Keep the original Final-ledger and input custody authority.

Upstream PR #1475 also addresses a *different-turn* reopening after a stall via `questionId` and `timelineTurns`. Classic lacks those canonical equivalents and must not guess same-question equivalence; this remains an explicit open item (`ID-02`).

## Audit coverage

Reviewed modules: `session/store.ts` completion semantics, `session/input.ts` claim/send/ACK and browser-unknown custody, `session/correlation.ts` strict MCP request ownership, `bridge.ts` recovery and provider-history backoff, `durable.ts` atomic pending writes, and 3.x Goal/Loop recovery boundaries, with existing fault-injection coverage. This is a **targeted independent source/contract audit**, not formal verification of every line of the full product.

New tests: positive same-turn native final with late `stalled`, negative unrelated turn and no-provider-final, and Bridge→input policy settled integration. The positive failed against the 3.1.18 source and passed after the patch.

## Other audit findings / open acceptance gates

1. Browser input in `state=browser` after an uncertain send can remain nonterminal across restart. This is intentional once sending has crossed the irreversible boundary; silently expiring or resending is unsafe. Implement exact native-user-message/claim reconciliation as a separate task, not by blind timeout.
2. Unattributed MCP calls still occur in real account usage where no matching ChatGPT page `request_id` is present during the evidence grace. Do **not** assign calls based on active tabs, tool names or timestamps. Investigate the provider's page identity coverage and add diagnostics before adjusting recovery behavior.
3. Full CoS text-input → real ChatGPT send → Assistant final → CoS UI E2E, 24–72 h endurance, multi-worker restart, and cross-platform packages remain separately gated. Do not equate CI PASS with these real-account acceptance gates.
4. Next WebRuntime and older dirty Classic worktrees were explicitly untouched.
