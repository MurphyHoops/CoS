## 3.1.15: Restore new-chat execution and harden browser recovery

CoS 3.1.15 repairs the local failure mode where a new ChatGPT tab could open but the queued
message never executed.

### Current ChatGPT composer and model picker

ChatGPT changed both the composer surface and the model-picker internals. The old
`#prompt-textarea` / `composer-intelligence-picker-content` path can now be absent, and the
provider exposes the selected model through its current model-list and power-selection state.

CoS now recognizes the current rich-text composer, follows the picker trigger's controlled
menu/dialog, and projects only an allowlisted model/version/effort snapshot from the current
provider state. Model selection is still proved from native state before CoS authorizes Send.
This fixes `Requested model or reasoning could not be confirmed` on fresh CoS-created chats.

### Browser-control and continuation recovery

Browser-control polling now has a separate authenticated budget and bounded retry for transient
429/network/server failures so a burst of restored ChatGPT tabs cannot starve the recovery plane.
Compact & Resume also keeps exact abandoned source-draft cleanup provenance durable until the
page proves that exact app-authored draft is gone. A manual browser input may reopen a conversation
only after the prior recovery episode is durably terminal and tool-free.

### Renderer subscription hardening

The preload boundary now rejects non-function event listeners instead of installing callbacks that
can later throw from IPC. The renderer also performs a bounded read-only state refresh every 15
seconds as a fallback for a missed contextBridge state push.

### Local validation

The repaired macOS arm64 package was installed locally and its native packaged-runtime smoke
passed, including MCP, Sharp, PTY, Tree-sitter and the in-process macOS desktop helper. The stable
browser companion self-refreshed to the matching 3.1.15 build, authenticated its wake channel, and
the live current-provider picker was observed and moved Medium -> High -> Medium without sending
a message.

App and companion are version 3.1.15. Bridge protocol remains 15.
